AI Tools & Automation for Solo Builders

Oct 9, 20266 min read
  • #ai
  • #tools
  • #productivity
  • #automation

Most “best AI tools” roundups are written for people who don’t ship code. This one has a single filter: does it save a solo developer measurable time in a normal week? If a tool can’t clear about 30 minutes a week, or replace a task you already do on a schedule, it’s a subscription you’ll forget to cancel.

Set the bar before you buy anything

Before adding a tool, write down the task it replaces and how long that task takes today. A release-notes chore that eats 20 minutes every Friday is worth $10/month. A chat UI you open twice is not. The trap for solo builders isn’t the price per tool — it’s the accumulated $60–80/month of “someday” subscriptions that each promise a workflow you never build.

Two rules keep this honest: pay with an API key and metered usage for anything you script (you’ll often spend under $2/month), and keep a paid seat only for tools that live in your editor or terminal where you already work.

Coding assistants: run one, not five

The three serious options overlap heavily. Pick the one that matches how you work, not the one with the loudest launch.

  • GitHub Copilot — best if you live in VS Code/JetBrains and want low-friction completion plus chat. Free tier exists; Pro is $10/month, Pro+ $39/month.
  • Cursor — an AI-first editor (a VS Code fork). Strongest for multi-file refactors and inline edits. Free Hobby tier; Pro $20/month, Ultra $40/month.
  • Claude Code — agentic edits from the terminal, good for “change this across the repo” tasks. Bundled with Claude Pro at $20/month, or metered via API.

Avoid stacking all three. They solve the same problem, and your muscle memory fragments.

A commit assistant you’ll actually use

Commit messages are cheap to generate and easy to verify, which makes them a perfect automation target. The llm CLI (from Simon Willison) is a thin wrapper over any API model:

#!/usr/bin/env bash
# ~/bin/ai-commit
set -euo pipefail
diff=$(git diff --staged)
[ -z "$diff" ] && { echo "Nothing staged."; exit 1; }

msg=$(printf '%s' "$diff" | llm \
  -s "Write one Conventional Commits subject line, max 72 chars. Output only the subject.")

git commit -m "$msg"

This saves a few minutes per commit and, more importantly, keeps history consistent when you’re context-switching between projects.

Automate review, not authoring

AI review catches the boring stuff — missing null checks, forgotten error handling, inconsistent naming — before a human ever looks. CodeRabbit is free for open source and roughly $12–24/month per developer for private repos. Its config is a single file:

# .coderabbit.yaml
language: en-US
reviews:
  profile: chill            # less nitpicky than "assertive"
  request_changes_workflow: false
  high_level_summary: true
  poem: false               # turn this off

Pair it with a CI gate so reviews don’t depend on remembering to run anything.

Automation beyond autocomplete

Release notes that write themselves

You already have the source of truth: your git log. Feed it to a cheap model and print user-facing notes. Using the OpenAI Python SDK:

# scripts/release_notes.py
import os, subprocess
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

def last_tag() -> str:
    return subprocess.check_output(
        ["git", "describe", "--tags", "--abbrev=0"], text=True
    ).strip()

log = subprocess.check_output(
    ["git", "log", f"{last_tag()}..HEAD", "--pretty=format:%s%n%b"],
    text=True,
)

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system",
         "content": "Write terse user-facing release notes grouped under "
                    "Added / Changed / Fixed. No fluff, no marketing."},
        {"role": "user", "content": log},
    ],
    temperature=0.2,
)
print(resp.choices[0].message.content)

At gpt-4o-mini rates (roughly $0.15 per 1M input tokens), this costs fractions of a cent per release. Run it as a make target and edit the output — you keep the editorial control without writing from a blank page.

Issue triage without a human first pass

GitHub Models exposes hosted models to Actions directly, so you can classify incoming issues on day one:

# .github/workflows/triage.yml
name: triage
on:
  issues:
    types: [opened]
permissions:
  issues: write
jobs:
  classify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/ai-inference@v1
        id: ai
        with:
          model: openai/gpt-4o-mini
          prompt: |
            Classify into exactly one of: bug, feature, docs, question.
            Reply with only the label.
            Title: ${{ github.event.issue.title }}
            Body: ${{ github.event.issue.body }}
      - run: gh issue edit ${{ github.event.issue.number }} --add-label "${{ steps.ai.outputs.response }}"
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

Two caveats worth internalizing: AI triage is a suggestion, so let it label but never auto-close. And treat the issue body as untrusted input — a malicious body can contain prompt-injection text.

Where AI costs you time

  • Security-sensitive code. Auth, crypto, and payment paths need a human who understands the threat model. Generated code that “looks right” is the expensive kind of wrong.
  • Generated tests. Models happily assert your current buggy behavior, cementing it as a regression test. Write the assertion yourself, let the model fill in boilerplate.
  • Tiny scripts. If the task is a three-line regex, the model’s latency and occasional hallucination cost more than typing it.
  • Hot paths. Never put an LLM call in a CLI’s critical path or a request handler where latency matters and determinism doesn’t exist.
  • Data you can’t send. Client code, keys, and regulated data belong in a local model (Ollama, LM Studio) or nowhere. Local models are free but need RAM; budget ~8GB for a small code model.

A realistic monthly stack

Tool Job List price (verify before buying)
Copilot or Cursor Completion + inline edits $10–20/mo
Claude Code / API Agentic + scripting $0–20/mo (metered)
CodeRabbit PR review Free OSS / ~$12–24
llm + API key Commit msgs, summaries usually < $2/mo
Ollama Private/local inference $0 (your hardware)

For most solo developers, one editor assistant plus a metered API key covers 90% of the payoff for well under $30/month. Add review tooling only after you have regular PRs to review.

Key takeaways

  • Pick one editor assistant. Copilot, Cursor, and Claude Code overlap; running several fragments your workflow for no extra capability.
  • Automate tasks with an obvious source of truth first — commit messages, changelogs, labels — because the output is cheap to verify.
  • Use metered API keys for scripts. The tasks worth automating are small and frequent, which is exactly where per-seat pricing overcharges you.
  • Treat AI review and triage as suggestions. Never let generated changes auto-merge or auto-close.
  • Skip AI wherever verification is expensive: auth, payments, crypto, and generated tests that lock in current behavior.
  • Keep private or regulated code local. A free Ollama model beats a leaked API key.
